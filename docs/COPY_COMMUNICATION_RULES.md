# Communication and release rules

## Sendable copy
- Client messages, outreach, follow-ups, replies and other sendable text should default to one clean copy-ready block.
- Write naturally and directly in the recipient's language.
- Keep paragraph count low and use only formatting that improves readability.
- Avoid em dashes, excessive headings, stacked one-sentence paragraphs, filler, generic corporate language and wording that sounds AI-generated.
- Lead with the final sendable text. Add notes only when they are genuinely needed.

## Release discipline
- Do not use Vercel production as a visual preview environment.
- Batch related changes into one coherent release instead of pushing micro-edits.
- Before a Vercel release, inspect recent team deployment/build activity and avoid competing with other active projects when the Hobby window is close to its limit.
- Prefer one verified production deployment per coherent package.
- A production change is complete only after the exact commit, READY deployment, production alias and live behavior are verified.
